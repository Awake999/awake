# 🎯 GRADING SOP — how every run gets graded against the SOP
*Alan's spec 8/30 ([verbatim](https://github.com/Awake999/awake/blob/claude/new-session-1ofk4w/ops/prompts/2026-08-30-format-grading-refinement-spec.md)). One grade file per protocol run, named `YYYY-MM-DD-run-<register#>-grade.md`, linked from that reply's footer.*

## 🏁 BRIEF: one file per run, graded literally against the SOP's own steps, results first, vertical, mobile.
**⏱ How a grade file flows:** 🏁 result line → 📊 numbers → 🔄 before/after → ✅resolved/⚠️remaining → 📜 SOP-step-by-step side-by-side → limitations+auto-fixes → 🧠 digest → plan + progress bars.

## Format rules (mobile-first)
- **RESULTS FIRST** — the top block answers "what was the end result?" before anything else: one-line conclusion, %s, before→after, resolved vs remaining, and a left-to-right ⏱ timeline of the run.
- **LITERAL SIDE-BY-SIDE** — each graded item opens with 📜 the SOP step being graded (its actual words), with the run's result indented beneath. Never grade against a paraphrase.
- **VERTICAL, never wide tables** — each item is a short stack you thumb-scroll, no left-right scanning.
- Every item carries, in this order:
  - ✅/❌ **What we did / did not do**
  - 🎯 **% we should have done vs % done** (only tool-verified work counts)
  - ⭐ **Quality grade**
  - 💬 **Why it got that grade**
  - 🔗 **Link straight to the work**
  - 🔄 **Before → After**
- Close every grade file with: **plan forward** · limitations that bit this run + the automatic fix · micro/macro progress bars.

## Grade scale
A = executed fully, verified, zero reprompts · B = executed, minor delta caught by Alan · C = needed a reprompt · D = needed 2+ reprompts or a checkbox-before-work violation · graded items never silently regrade — corrections append.
