## The asks, one line each, verbatim-anchored
1. Program this into the SOP, built into all four lanes and the project itself; all current AND new lanes use it as a base.
2. Every user prompt is broken down verbatim into checklist form — fully heard, optimized for checkability on big text blocks, NO original fidelity lost.
3. That checklist is presented back to the user to confirm/deny + catch anything missing before work.
4. The confirmed checklist is stored in the database, hard-coded, always referenceable for the SOP.
5. Claude adds its own suggestions/insights to improve the plan — for AI AND for humans.
6. Output is UI-friendly for beginners AND masters — never sacrificing beginners — in harmony with how AI/code operates.
7. The SOP points every lane and every Claude agent to respond with this checklist process.
8. After the checklist + additions: ASK to execute; execute only on approval.
9. After execution: a cross-off table with columns — (a) completed or not, (b) status, (c) % completion, (d) quality rating, (e) why rated that way, (f) suggested improvements, (g) clickable hyperlink jumping straight to the work, (h) before-and-after ("before it looked like this, after it looks like this").
10. THIS reply itself models the process (prime example).
11. Confirm the SOP being integrated + its location + suggestions to navigate to full implementation.
12. All future + current lanes connected to this as standard operating procedure.
13. Every final output ends with buttons (with Claude suggestions) + a timeline tracker + a progress tracker of micro and macro.
14. The systemized checklist is stored with a link, compaction-proof, so nothing is forgotten.
15. Claude adds its own suggestions to optimize accuracy/precision across prompts→execution→follow-through→quality, specifically against compaction/summary bottlenecks.
16. The plan block ends with: suggested MODEL + EFFORT + reasoning (incl. whether ultracode is needed).
17. That block includes: estimated tokens, estimated time, sustainable duration at that effort before limits — accounting for token limits, daily/weekly/monthly usage, Fable 5 usage, plan usage (currently 20x max; enterprise/add-on suggestions welcome).
18. RAW information first, optimized plan second, options third — never pre-shrink the answer to save tokens.
19. All of this lives in the SOP so it never has to be repeated.
20. Flag when Fable 5 high isn't enough (extra/max/ultracode) — for the plan AND during execution; offer a rerun if the plan itself was under-powered.
21. Every response identifies which model/effort served the prompt (ask if unknown) + recommends the right one; offer rerun when warranted.
